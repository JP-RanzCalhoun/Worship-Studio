# Audit reconciliation — ChatGPT + Muse (2026-11-17)

Sources: the audit thread in Slack #claude-chatgpt (ChatGPT 3 + 3 posts, Muse 4 + 2 posts). Claude checked every finding
below against the code, and checked every repository and licence claim against primary sources (GitHub, PyPI, issues, model cards).

## Verdict

Both reviewers fail the gate (ChatGPT 2.8/5, Muse 2.7/5). Claude agrees:
- **Personal / church rehearsal use:** viable now, with the known cautions.
- **Public release:** not ready (licences, model weights, browser capture terms).
- Neither reviewer recommends a rewrite or adopting a DAW. Claude agrees.

Where they agree (and the code confirms): recording trust (device identity, calibration, effects), data safety
(chart merge, take recovery), reliability (bridge, jobs, exporter), QA baseline, and roadmap order
(**thin M4 "Sunday workflow" before M3 VST3**).

## Licence facts (checked 2026-11-17)

- **Demucs weights are NOT MIT.** Maintainer (demucs #327): weights "are provided only for scientific purposes"; the new
  README calls the weight licence "not clear". `docs/LICENSES.md` says MIT/OK — **wrong, must be fixed**. Round 2
  wording (ChatGPT, agreed): the weights are **uncleared for non-scientific use**, church use included. Personal
  experiments are a low practical risk, but that is not a licence. Replace them or get written clearance (JP decides).
- **UVR Karaoke 2:** research-only, not bundled, until the checkpoint itself has a clear redistributable licence
  (an MIT wrapper/GUI is not proof for the weights). Record the "MIT + credit" wording with that caveat in NOTICE.
- **BS-RoFormer-SW weights:** `license: unknown`, original uploader deleted. Treat as unlicensed; never bundle.
- **beat_this:** code and weights MIT. **python-audio-separator:** MIT, v0.48.0 out, has per-model SHA-256 checksums.
- **StemDeck:** AGPL-3.0 since v0.21 (Apache-2.0 up to 0.20.0). ChatGPT was right, Muse was wrong.
- **ChordSheetJS:** GPL-2.0-only — cannot ship with AGPL JUCE or closed source. Reference only.

## Plan (proposed; roadmap change needs JP's OK)

**Gate before A:** a reviewed first git commit + tag (JP says "commit").

**Phase A — Stop losing work, stop hanging (1 session).** Also the accessibility foundations before any new screens:
focus-trapped confirm dialog, semantic controls (real buttons/links), zoom blocked only on the Browser page. Bridge timeout + re-hook; chart merge keeps every user-touched
chord and merges sections per section (one undo step); reset clears "Ready"; F#/C#/G# keys spelled with sharps (tonal);
unique stem folders; export: both channels, rate check, same output stage as live; browser capture fills dropouts and
restores video volume; cancel kills the whole process tree; job-exit race; tuner cleanup; quiet stems kept muted;
pin beat-this 1.1.0 and audio-separator 0.48 (done: beat-this 1.1.0; audio-separator still 0.47.0, see ROADMAP), record model hashes; `npm test` script; fix LICENSES.md.

**Phase B — Trustworthy recording.** Device IDs instead of names, Refresh inputs; first-run setup wizard (pick E2 +
PD200X, check Windows effects, 10-second signal test, latency calibration with a click); manual nudge; take delete
(Recycle Bin), recovery, storage meter; real 5-minute E2 + PD200X test.

**Phase C — "Sunday mode" (the core feature for JP; thin M4).** (Round 2 additions from ChatGPT and Muse marked ✚)
- **Service order:** drag songs into a setlist; per song: key, capo, tempo, click, count-in, transition note.
  ✚ Set runtime: per-song length, set total vs the service slot, time for capo changes/transitions.
  ✚ Import the week's order (CSV / ChordPro first, Planning Center later) instead of retyping.
- **Arrangement ✚:** section labels; skip/repeat sections per song (e.g. no Verse 2, Chorus ×2); vamps, tags, endings;
  live **hold / next / previous section** ("stay on this chorus until I tap").
- **Timing ✚:** per-section time signature (4/4, 3/4, 6/8) and tempo map; count-in and cue choices per song.
- **Lyrics + chords view:** start with ChordPro paste/import and user correction. Chords over the words, letters **or
  Nashville, with capo-aware open/CAGED shapes** ✚. Big-text stage view. Automatic lyrics (faster-whisper) is an
  optional later add-on, local only, with an edit pass before the stage view ✚; never export lyrics by default ✚.
- **Hands-free:** Bluetooth page-turner and MIDI pedal: next song, next section, hold, play/stop, loop.
  ✚ Pedal "learn" mode and safe mappings (a press can't change songs by accident).
- **Per role ✚:** transpose and mute presets per role (guitarist mutes reference guitars, singer mutes lead vocal).
- **Practice tools:** section loop that ramps 70% → 100% tempo; per-section key changes; add9/sus/slash chords (tonal).
- **Rehearsal pack:** export a folder per service that works offline on its own (practice mix without reference
  guitars, click version, printable chart PDF). ✚ CCLI number per song and a song-list export for CCLI reporting.
- **Offline preflight ✚:** before Sunday, flag missing audio, chart, cues, models or pack files.

**Phase D — UX polish.** React Aria dialogs/focus; zoom only blocked on the Browser page; meters with text (dB, CLIP);
"next step" guidance; the north-star test: **one unfamiliar song → corrected capo chart, guitars muted, loop, click/cues
and an aligned take in under 15 minutes.**

**Later:** live VST3 (only after choosing: dual USB = dry record + hardware monitoring; live effects = one multi-input
ASIO interface), video, other platforms.
